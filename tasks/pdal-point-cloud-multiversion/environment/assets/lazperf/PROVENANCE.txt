Provenance — laz-perf 3.2.0 as shipped in this image
====================================================

Source      : laz-perf, the LAZ compression library
Upstream    : https://github.com/hobuinc/laz-perf  (tag 3.2.0)
Tarball     : https://github.com/hobuinc/laz-perf/archive/refs/tags/3.2.0.tar.gz
Tarball sha256:
  8baf81c8ba03fe3b9e33abe2a1b49760ad1514e9daad9c852a6198fb976d8a14

Contents of lazperf/ are copied verbatim from
laz-perf-3.2.0/cpp/lazperf/ in that tarball; nothing in lazperf/ was edited.
COPYING is that tarball's COPYING, unedited.

Why 3.2.0: it is the newest version this task's window itself names -- upstream's
2.5.0 tree vendors laz-perf 3.2.0 (steps/05-overwrite-guard/solution/upgrade.patch,
which bumps the vendored copy's version macros from 3.0.0 to 3.2.0) -- and its
VLR API is identical to 3.1.0's, which is the API the 2.4.0-level code needs
(`vlr_header::data()`, `eb_vlr::addField(const ebfield&)`, `copc_info_vlr`).
Pristine 3.0.0 does not have that API and does not compile; 3.1.0 and 3.2.0
differ only in lazperf_base.hpp's version macros (verified with diff -rq), so
3.2.0 is 3.1.0's code with the version the ladder's middle expects.
