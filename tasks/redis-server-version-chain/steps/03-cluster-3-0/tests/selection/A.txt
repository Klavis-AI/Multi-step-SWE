# --- 06-slave-stop-cond.tcl (15) ---
#
# A cluster unit is one sequential script, not a bag of independent cases: the
# adapter skips the BODY of an unselected test, so dropping a name here deletes
# whatever that body set up for the names that follow. Four of this unit's names
# are load-bearing and must stay selected:
#   "Slaves of #0 is instance #5 as expected"  sets $port0, which
#       "Break master-slave link ..." passes to CLIENT KILL;
#   "Instance #5 synced with the master"       waits for master_link_status:up,
#       without which that CLIENT KILL has no master link to kill, EXEC returns
#       {ERR No such client, OK}, and the test aborts leaving R 5 deferred with
#       an unread reply -- a connection the harness then reuses for every later
#       unit, which reads the stale +QUEUED and dies on "Cluster nodes are
#       reachable";
#   "Slave #5 is reachable and alive"          is the direct check that the
#       connection above is not poisoned;
#   "Slave #5 should not be able to failover"  carries the `after 10000` that
#       lets cluster-slave-validity-factor take effect before
#       "Cluster should be down" reads cluster_state.
# Selection is by name, so each of these also runs (unscored) in the other units
# that contain it, which is what restores their sequencing too.
