# Every one of the 67 sites is inside one of them. Nothing else on this
# tree touches the security API, so the migration is a DELETION and not an
# edit-in-place, and the population this leg scores is the population the
# deletion removes.
#
# WHY IT IS SCORED AS A POPULATION AND NOT AS "no doPrivileged remains". Two
# ways out of an AccessController are not edits at all. A tree that deletes a
# SecurityActions class WITHOUT removing its callers does not compile, which
# C-1 catches. A tree that replaces the body of every doPrivileged with a
# direct call and LEAVES the seven classes as empty shells compiles, behaves
# identically, and leaves 67 records standing -- because the plugin reads
# references, and a class that still imports AccessController still refers to
# it. That tree is what this population is for.
#
# AND THE LEG IS NOT ONLY THIS FILE. A departure scored alone pays deletion,
# so C-2 is min()'d against the PAYLOAD the deletion has to leave behind:
# 13 sites in these same 7 files -- the 7 `newinstance form=ctor`
# calls the unwrap ladders existed to unwrap, and the 6
# `setAccessible` reads in the annotation scanners, each of those six inside
# a method that also held a doPrivileged. They are counted against the file
# list THIS file's rows imply, not against a second frozen list, and they are
# the same 13 on the golden. target.priv.hold and its two parts carry them.
#
# OF THE FOUR NAMES, TWO ARE THE SAME DEPARTURE. PrivilegedActionException and
# PrivilegedExceptionAction are both in JEP 486's list and the classes that
# declare them are deleted whole; the plugin counts them separately because
# they are separate types, and both must reach zero.
