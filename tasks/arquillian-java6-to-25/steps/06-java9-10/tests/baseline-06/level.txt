# The class-file major version this rung targets.
#
# Staged rather than written into the verifier, for one reason: C-1 and the
# step's instruction have to be talking about the same number, and on a
# thirteen-rung ladder the number changes at six of the rungs. A literal in
# test.sh is a literal that gets copied forward and not edited -- which is the
# failure that reads as a pass.
#
# 54 is Java 10. The ladder: 50 = Java 6 (steps 01-02), 51 = Java 7 (03),
# 52 = 8 (04-05), 54 = 10 (06), 55 = 11, 61 = 17, 65 = 21, 69 = 25.
#
# THIS RUNG MOVES IT, 52 -> 54, and that makes the class-file level this step's
# must-flip: C-1 owns it. B-4 -- which at step 05 asked for "one major, and it
# is the one level.txt names" -- is restated here as "one major, and it is not
# below 52", so that the number is scored once rather than twice and family B
# still reads 1.0 on the tree this step is handed.
#
# 54 and not 55: the migration line's rung is "Java 9/10", `var` is a Java 10
# feature, and `--release 10` is the flag that both caps the API at 10 and
# emits 54. Java 11 is the next rung's business.
#
# The scorer validates this on read and refuses to grade if it is missing or
# implausible, so that a staging mistake cannot become a zero that looks like a
# measurement about the tree.
major=54
