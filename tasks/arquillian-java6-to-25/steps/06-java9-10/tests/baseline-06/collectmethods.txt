# Step 04 -- the 24 <file>#<method> buckets holding a collecting enhanced `for`
# at the baseline, and C-3's arrival denominator.
#
# Copied out of baseline/source.txt's own foreach[...] records, not retyped:
#
#   sed -n 's/^foreach\[[0-9]*\]=//p' baseline-step04-source.txt \
#     | awk '$0 ~ /collect=yes/ {split($1,a,":");
#              for (i=2;i<=NF;i++) if (substr($i,1,3)=="in=") m=substr($i,4);
#              print a[1] "#" m}' | sort -u
#
# This file replaces streamfiles.txt as what C-3's arrival half is POINTED AT,
# and the reason is round 2 of this step's static review. The file-level set
# below it asks "does this file hold a pipeline?", and fourteen `xs.stream()
# .count();` statements -- one per file, computing nothing, next to twenty-four
# loops rewritten as `dst.addAll(src)` -- answer yes to all fourteen while
# converting nothing. The census half of C-3 does fall for such a tree, because
# `addAll` really does remove the loops; so the two remaining halves both read
# full and 0.60 of family C is paid for a rewrite that never wrote a pipeline.
#
# A method is the scope the instruction actually names: "those 24 become stream
# pipelines" means the pipeline is where the loop was. The 24 loops sit in 24
# distinct buckets -- no two of them share one -- so this set is strictly
# narrower than the 14 files and has the same denominator as the departure half,
# which is the population the whole gate is about.
#
# `in=` is the OUTERMOST enclosing method, by simple name. Outermost because
# this step converts anonymous classes to lambdas, and an innermost reading
# would give a loop inside an anonymous body one identity before the step and
# another after it. See SourceScan.enclosingMethod().
#
# Measured against the golden: the 24 buckets holding a stream PRODUCER, and
# the 24 holding a STAGE, are both identical to these 24 -- not merely the same
# size, and with nothing left over.
