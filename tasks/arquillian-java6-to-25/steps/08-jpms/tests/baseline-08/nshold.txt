# Step 07 -- C-3's frozen population: every (package, <file>#<method>) pair
# holding a javax reference that MUST NOT MOVE.
#
# The package is part of the key and not a comment on it. One method can
# reference two javax packages -- InitialContext plus a JMX type, say -- and if
# the bucket alone were the key, moving one of the two would leave the bucket
# still occupied and the hold would read full. 43 pairs over 112 references.
#
#   javax.enterprise  32 refs, 16 pairs   CDI 1.0, against Weld 1.1
#   javax.management  40 refs, 10 pairs   JMX -- still javax in Java 25
#   javax.naming      24 refs, 11 pairs   JNDI -- still javax in Java 25
#   javax.servlet      9 refs,  3 pairs   Servlet 2.5/3.0, against the 2011 jars
#   javax.xml          4 refs,  1 pair    JAXP -- still javax in Java 25
#   javax.inject       3 refs,  2 pairs   Weld 1.1's; see nsmove.txt
#
# TWO OF THOSE SIX ARE NOT A DEFERRAL AT ALL. javax.management and javax.naming
# and javax.xml are JDK packages: they were never part of Java EE, Jakarta
# never took them, and they are spelled javax in Java 25 exactly as they are
# here. A candidate who "finishes the namespace migration" by rewriting them
# produces a tree that does not compile, and this file is the instrument that
# says so before the compile does.
#
# This is why C-3 is SCALED BY C-2 rather than scored on its own. All 43 pairs
# hold on the input tree, which has migrated nothing; an unscaled C-3 would pay
# that tree 0.32 of family C for standing still, and the floor arithmetic at the
# foot of test.sh is where that shows up as a number.
#
