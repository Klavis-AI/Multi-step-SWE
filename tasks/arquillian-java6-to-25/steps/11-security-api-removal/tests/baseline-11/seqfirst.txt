# TWO INDEPENDENT CONDITIONS, AND A SITE CONVERTS ONLY IF IT PASSES BOTH.
# `getFirst()` is on SequencedCollection (JEP 431), which List and Deque
# extend and Set, Collection and a bare Iterable do not -- so a LinkedHashSet
# held in a `Set` variable has a first element at run time and no
# `getFirst()` at compile time. And the throw must not change:
# `iterator().next()` and `getFirst()` both throw NoSuchElementException,
# but `get(0)` throws IndexOutOfBoundsException, so a get0 site converts only
# where an enclosing condition tests the SAME receiver expression.
#
# THE CONV HALF IS SCORED ON A PRESENCE. The method must have LOST its
# seqfirst record AND GAINED a `seqnew` one whose op is `getFirst`
# SPECIFICALLY. `getLast()` and `reversed()` are recorded by the same gate
# and are filtered out of the arrival half: every site here reads the FIRST
# element, `getLast()` reads a different one, and `reversed()` is not a read
# at all. `seqnew` reads 0 across this whole tree on the way in, which is what
# makes that a clean measurement rather than a threshold. Without it, deleting
# the call would read exactly like rewriting it.
