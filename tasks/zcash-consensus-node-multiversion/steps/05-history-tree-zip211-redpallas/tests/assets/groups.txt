# `workspace-checks` runs `--all-features --all-targets`, not bare
# `--all-targets`: from v1.0.0-alpha.8 on, zebra-chain/benches/block.rs uses
# `zebra_chain::block::tests::generate::*` while block.rs gates that module

#
# Two headline items of this milestone have NO driver, because neither is
# reachable from outside its crate in this codebase revision:
#
#   * The ZIP-221 MMR itself -- `zebra_chain::primitives::zcash_history` is
#     `pub mod`, and `Tree`, `Entry` and `NodeData` are `pub struct`, but
#     every constructor and method on them (`new_from_block`, `new_from_cache`,
#     `append_leaf`, `append_leaf_iter`, `truncate_leaf`, `hash`, `new_leaf`,
#     `new_node`) is private, and the struct fields are private too. An
#     integration test is a separate crate, so the module is inert from there:
#     the only observable output of the MMR is the root it produces, which is
#     what `chain-history-commitment` scores through `ChainHistoryMmrRootHash`.
#     Step 06 makes the tree itself public as `HistoryTree` and scores it.
#   * The batched RedPallas *service* -- `zebra_consensus::primitives` is
#     `mod primitives;` (private) in zebra-consensus/src/lib.rs, so
#     `primitives::redpallas::{VERIFIER, Verifier, Item}` cannot be named from
#     a test. The batch math underneath it lives in zebra-chain and is public,
#     and that is what `redpallas-batch` scores.
#
# Likewise `zebra_consensus::transaction::check::disabled_add_to_sprout_pool`
# (ZIP-211) and the v5-before-NU5 rule are behind `mod transaction;`, so
# `consensus-error-surface` scores the public error surface those rules raise
# rather than the rules themselves. See docsrc/step05/TEST_INTERFACE.md's
# negative-space section.
