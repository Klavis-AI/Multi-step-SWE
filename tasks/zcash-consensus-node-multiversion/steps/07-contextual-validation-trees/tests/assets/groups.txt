# Every arg below was re-derived with `grep -c '^#\[test\]'` after the last
# edit to its driver, and matches the executed count in the green run.
#
# `workspace-checks` runs `--all-features --all-targets`, not bare
# `--all-targets`: from v1.0.0-alpha.8 on, zebra-chain/benches/block.rs uses
# `zebra_chain::block::tests::generate::*` while block.rs gates that module
# behind `#[cfg(any(test, feature = "bench"))]`, so the bare form does not
# compile the released tree. Upstream CI runs `--all-features --all-targets`.
#
# Why the new tier is split six ways: this milestone adds one idea --
# "validation needs context the block does not carry" -- in four independent
# places, and each place has its own sign, ordering or domain convention that
# a plausible-looking wrong implementation still satisfies elsewhere.
#
#   value-balance-pools         the ValueBalance ledger type and its algebra
#   amount-sum-and-zero         the Amount constraint arithmetic underneath it
#   transaction-value-balance   one transaction's effect on the four pools
#   ordered-utxo-coinbase-spend ordered UTXOs + coinbase spend restrictions
#   note-commitment-trees       Sapling/Orchard incremental Merkle frontiers
#   state-contextual-surface    the zebra-state types the above land in
#
# What has NO driver, because it is not reachable from an integration test:
#
#   * `ValidateContextError`'s contextual variants. All of
#     DuplicateTransparentSpend, MissingTransparentOutput, EarlyTransparentSpend,
#     UnshieldedTransparentCoinbaseSpend, ImmatureTransparentCoinbaseSpend,
#     DuplicateSaplingNullifier, DuplicateOrchardNullifier and
#     InvalidRemainingTransparentValue are `#[non_exhaustive]` *per variant*,
#     so no external crate can construct one and none has a public constructor.
#     The two note-commitment-tree variants are the exception -- they are
#     `#[from]` conversions -- so `state-contextual-surface` scores those plus
#     the observable error chaining (`CommitBlockError`, `CloneError`) that
#     every other variant is delivered through.
#   * The checks that raise those variants. `zebra_state::service::check`
#     (utxo.rs, nullifier.rs, anchor.rs) is behind `mod service;`, and
#     `ContextuallyValidBlock` -- the type those checks produce -- is
#     `pub(crate)`. Their inputs are public, so `ordered-utxo-coinbase-spend`
#     scores the two public predicates the transparent rules are built from
#     (`Transaction::coinbase_spend_restriction` and the OrderedUtxo ordering)
#     rather than the private check functions.
#   * `zebra_consensus::transaction`'s use of all of the above: still
#     `mod transaction;` (private) at this tag.
#
