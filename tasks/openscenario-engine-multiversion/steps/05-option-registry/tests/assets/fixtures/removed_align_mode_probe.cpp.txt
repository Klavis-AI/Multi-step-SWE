// NOT a driver -- the extension is deliberately `.cpp.txt`, not `.cpp`, so the
// runner's `for src in /tests/assets/drivers/*.cpp` loop (test.sh.in) never
// picks this file up and never tries to link it into the driver set. It is
// compiled on purpose, from removed-api/a-align-mode-z-removed.sh, as a
// compile-must-fail probe.
//
// Why it exists: instruction R7 promises that code still calling a removed
// align-mode entry point "must fail to link" against the target build. Every
// other check in this group reads the dynamic symbol table of the candidate's
// shared libraries, which catches a symbol that was genuinely deleted but NOT
// one that was merely hidden from `nm -D` (a version script, -Wl,--exclude-libs,
// or a stray static archive on the link line all hide a symbol while leaving it
// resolvable). This translation unit is the only place in the suite that calls
// a removed symbol, so it is the only check that observes the rejection the
// document actually promises rather than the removal alone.
//
// The call goes through the PUBLIC HEADER, with no local redeclaration: that is
// the whole point. At v2.44.2 the declaration is gone from esminiRMLib.hpp, so
// compilation stops at the undeclared identifier and the translation unit never
// reaches the linker. A redeclaration here would defeat the probe by compiling
// cleanly against a stale header. At the start tag the declaration is present
// and the symbol is exported, so this compiles -- which is why the assertion
// belongs to the `new` tier: it fails at the start tag, where the removed family
// is still part of the API, and passes at the target.
//
// The pointer indirection keeps the call from being folded away, so a build that
// hid the symbol instead of removing it would still get an undefined reference
// out of this translation unit if it were linked.
#include <esminiRMLib.hpp>

volatile int test_note = 0;

void rm_set_align_mode_probe(int handle, int mode)
{
    void (*fn)(int, int) = &RM_SetAlignMode;
    fn(handle, mode);
    test_note = 1;
}
