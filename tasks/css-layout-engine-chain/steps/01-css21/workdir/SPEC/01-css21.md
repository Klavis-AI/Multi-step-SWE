# Normative references for this milestone

The behaviour required of the engine is **exactly** what these documents say.
Nothing in this repository redefines them, and where this file and a
specification disagree, the specification wins.

## What is measured

Every document is laid out at 800x600 from a `file://` URL and compared
against Chrome for Testing 153.0.8010.36. For each measured element the check is
its **border box** -- `x`, `y`, `width`, `height` from `Get Element Rect` -- and
the resolved values of `display`, `width` and `height`.

A rect is correct when each of the four numbers is within **0.5 CSS pixels** of
the reference. A resolved value that is a length is compared numerically to the
same tolerance; a keyword must match exactly.

## CSS 2.1 — <https://www.w3.org/TR/CSS21/>

W3C Recommendation, 7 June 2011. The chapters this milestone rests on:

* **§5 Selectors** — <https://www.w3.org/TR/CSS21/selector.html>
  the documents select with type, universal (`*`), class, id, descendant
  and child (`>`) selectors, and with the **attribute presence** selector
  `E[att]` (§5.8.1). `E[att]` is easy to leave out and expensive to leave out:
  a rule it guards is dropped whole, so a document can lose every box it
  positions rather than one property. Specificity is §6.4.3, and `!important`
  §6.4.2.
* **§8 Box model** — <https://www.w3.org/TR/CSS21/box.html>
  content, padding, border and margin edges; **§8.3.1 collapsing margins**.
* **§9 Visual formatting model** — <https://www.w3.org/TR/CSS21/visuren.html>
  §9.2 block and inline boxes and anonymous box generation; §9.3 positioning
  schemes; **§9.4.1 block formatting contexts**, §9.4.2 inline formatting
  contexts; **§9.5 floats** and clearance.
* **§10 Visual formatting model details** — <https://www.w3.org/TR/CSS21/visudet.html>
  §10.1 the containing block; §10.3 width calculations including the
  shrink-to-fit and absolutely-positioned cases; §10.4 minimum and maximum
  widths; §10.6 height calculations; §10.8 line height and leading.
* **§11 Visual effects** — <https://www.w3.org/TR/CSS21/visufx.html>
  §11.1.1 **overflow**: a value other than `visible` establishes a block
  formatting context, and a scrolling mechanism occupies space taken from the
  element's content area. The documents set the scrollbar's size themselves, in
  their own stylesheet.
* **§16 Text** — <https://www.w3.org/TR/CSS21/text.html>
  **§16.6 white space processing**.
* **§8.4, §9.10** — <https://www.w3.org/TR/CSS21/visuren.html#direction>
  `direction` and the placement it selects; the documents use both `ltr` and
  `rtl` containing blocks.

## The properties this milestone uses beyond CSS 2.1

* `box-sizing` — CSS Box Sizing Level 3,
  <https://drafts.csswg.org/css-sizing-3/#box-sizing>. `border-box` makes
  `width` and `height` set the border box.

## The rendering environment these documents assume

Documents that declare no font, and documents that rely on the browser's default
element styling, are laid out against the **HTML user-agent stylesheet** — CSS 2.1
Appendix D, <https://www.w3.org/TR/CSS21/sample.html>, as implemented by the
reference browser. The values the documents depend on:

* `body { display: block; margin: 8px }`
* `p { display: block; margin: 1em 0 }` — and `1em` is the **16px** default font
  size, so a paragraph's margins are 16px and an empty paragraph's line box is
  18px tall (a 16px font whose `normal` line-height rounds to 18px).
* `div`, `p` and the other flow containers are `display: block`; `span` is inline.

**The scrolling mechanism.** `overflow: scroll` and `overflow: auto` reserve space
for a scrollbar, and CSS 2.1 §11.1.1 does not fix its thickness. The documents set
it themselves, with the non-standard `::-webkit-scrollbar` pseudo-element in their
own stylesheet:

```css
::-webkit-scrollbar { width: 15px; height: 15px; }
```

An engine must honour that declaration — **15 CSS pixels on the relevant axis,
taken from the element's content area** — for the documents that use it.

## Table display types (§17.2)

Two of the documents use `display: table`, `display: table-row`,
`display: table-cell`, `display: table-row-group` and
`display: table-column-group`, and every element they generate is compared — the
boxes, their `display` and their geometry. What they exercise is **table box
generation** — the table, row and cell boxes those values generate, and the
anonymous boxes §17.2.1 inserts where the markup omits a required ancestor — and
the geometry the resulting boxes are given, which is compared like any other box.

The rest of §17 is not measured at this milestone: the column-width distribution and
row-height algorithms (§17.5), `border-collapse` (§17.6.2), `table-layout:
fixed`, captions and `empty-cells`.
